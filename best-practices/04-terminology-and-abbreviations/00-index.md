# 04. Terminology and Abbreviations

## Chapter Status

- Status: Reviewed Draft
- Editorial maturity: review-ready
- Normative readiness: informative only
- Open drafting points: no

## Purpose

This chapter defines the controlled vocabulary used throughout the Dynamic Software Licensing best practices.

Its purpose is to ensure that key concepts are described consistently across the repository and that contributors, reviewers, and readers share a common understanding of the main terms used by the DSL initiative.

## Role Within the Best Practices

Terminology is a foundational part of the Dynamic Software Licensing best practices.

A consistent vocabulary is necessary to:
- avoid ambiguity,
- reduce duplicate concepts,
- prevent the use of multiple labels for the same idea,
- support clearer architecture, API, conformance, and requirement chapters,
- make the best practices easier to review and evolve over time.

This chapter should therefore be treated as a reference point for the rest of the document.

## Scope of This Chapter

This chapter covers:
- core terms,
- architecture-related terms,
- license and policy terms,
- operational terms,
- abbreviations used throughout the best practices.

It establishes the working vocabulary needed to keep the rest of the best practices coherent
without attempting to catalog every implementation-specific detail.

## Controlled Vocabulary Principle

Where a term is defined in this chapter, contributors should use that term consistently throughout the repository.

Contributors should avoid:
- introducing synonyms for established concepts,
- renaming concepts locally within a chapter,
- using platform-specific wording as the default term,
- mixing conceptual terms and implementation labels without explanation.

If a term needs to be changed, the change should be made deliberately and consistently across all affected chapters and annexes.

## Structure of This Chapter

This chapter is organized into the following subchapters:

### 01. Core Terms
Defines the most central concepts used across the best practices.

### 02. Architecture Terms
Defines architecture-related vocabulary used in the reference model and related sections.

### 03. License and Policy Terms
Defines terms related to licensing behavior, entitlement, lease handling, policy handling, and related concepts.

### 04. Operational Terms
Defines terms related to operation, lifecycle handling, observability, migration, and deployment behavior.

### 05. Abbreviations
Defines recurring abbreviations used throughout the best practices.

## Controlled Vocabulary Maintenance

This chapter should be treated as the repository's controlled vocabulary baseline for the
review draft.

If review feedback requires term changes, the update should be applied consistently across the
main document, relevant annexes, and any affected schema or API descriptions.

## Relationship to Other Chapters

This chapter supports and informs:
- the scope chapter,
