# Annex H. Persona Mapping

## Purpose

This informative annex summarizes how the main personas introduced in Chapter 05 map to the
most important DSL concern areas.

## Persona-to-Concern Mapping

| Persona | Primary concern areas |
| --- | --- |
| Director of Engineering | resilience, portability, predictable operational behavior |
| Operations and DevOps Engineer | automation, observability, repeatable lifecycle handling |
| Broadcast Engineer or Production Operator | continuity, low-friction activation, emergency flexibility |
| Finance and Procurement Lead | metering transparency, forecastability, modality clarity |
| Security and Compliance Lead | least privilege, auditability, trust boundaries |
| ISV Product and Commercial Owner | revenue protection, adoption friction, portfolio flexibility |
| ISV Licensing Architect | lifecycle correctness, token trust, interoperability |
| ISV Support and Customer Success Lead | diagnosability, explainable behavior, support scalability |
| SI Solution Architect or Integrator | semantic consistency, automation reuse, hybrid reliability |
| Platform and Infrastructure Stakeholders | workload identity, secure integration, operational fit |

## Interpretation Notes

- Multiple personas often converge on the same requirement area for different reasons.
- Operational transparency is relevant to both technical and commercial stakeholders.
- Identity-based binding is both a security concern and an enabler for mobility and failover.

## Relationship to the Main Document

- Chapter 05.01 defines the stakeholder groups.
- Chapter 05.02 defines the detailed persona perspectives.
- Chapter 05.04 derives requirement themes from these concerns.

## Annex Positioning

This annex provides a compact review aid for checking whether the draft remains balanced across
stakeholder perspectives.
